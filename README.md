# RSNA Knee Abnormality Detection

Code for the Kaggle competition **RSNA Knee Abnormality Detection**: study-level,
multi-label classification of 12 findings from knee MRI DICOM series.

```
ACL, MCL, Medial Meniscus, Lateral Meniscus, Medial OA, Lateral OA,
PF OA, Effusion, Synovitis, Baker's, Contusion, Fracture
```

The approach has two parts:

1. **Labels from radiology reports.** The competition's `train.csv` has numeric targets for
   only 58 of 4407 studies, but every study has a free-text report. An LLM (Qwen,
   served with vLLM through an OpenAI-compatible API) reads each report and extracts a
   status per finding. The statuses become soft targets in [0, 1] (`train_v<N>.csv`).
   A set of 208 studies read by radiologists serves as the evaluation reference and is
   never used for training.
2. **A 2.5D multiple-instance image model.** One series is picked per plane
   (sagittal / coronal / axial). Adjacent-slice triplets go through a 2D encoder
   (EfficientNet-B0 by default; EfficientNetV2-S, RadImageNet ResNet-50 and DINOv2 ViT-S/14
   are also available). Masked mean/max pooling runs over the slices, and a small head
   predicts the 12 logits.

Our best public leaderboard score was **0.942** (macro ROC-AUC), from a single
EfficientNet-B0 model at 320 px trained on `train_v8` labels. Label quality made the
largest difference: each cleaner label table gave a clear gain, while most architecture
changes made little difference.

> **Data is not included.** Get the DICOMs and CSVs from the competition page and agree to
> its rules. Paths in the configs (`F:/Kaggle/data`, `/ai-storage/...`) are from our
> machines; change them to yours.

## Setup

Python 3.11 and a CUDA GPU (developed on an RTX 5080, 16 GB; Windows and Linux).

```bash
conda create -n kaggle_2026 python=3.11
conda activate kaggle_2026
# install torch/torchvision first, using the index URL PyTorch documents for your CUDA driver
pip install -r requirements.txt
```

Compressed DICOM transfer syntaxes need `pylibjpeg` + `pylibjpeg-libjpeg` (or `gdcm`).
The competition export works with plain pydicom.

## Quick start

Run all commands from `src/` (or set `PYTHONPATH=src`). Start by setting
`paths.data_root`, `paths.cache_dir` and `paths.train_csv` in the config.

```bash
# 0. Checks that need no data
python -m knee_mri.cli selftest
python -m knee_mri.cli train --mode synthetic --n-studies 16 --epochs 3

# 1-3. Validate inputs, select series, build the preprocessed cache, inspect QC, make folds
python -m knee_mri.cli validate-schema
python -m knee_mri.cli build-manifest
python -m knee_mri.cli build-cache --set data.image_size=320
python -m knee_mri.cli qc --n-studies 12
python -m knee_mri.cli make-splits

# 4-5. Sanity overfit, then train one fold and write its report
python -m knee_mri.cli train --mode overfit --n-studies 8
python -m knee_mri.cli train --mode fold --set split.fold=0 --set data.image_size=320
python -m knee_mri.cli report work/runs/<dataset>/<run-name>
```

In practice, training is started with the runner scripts in the repository root. The
first argument is an optional run-name prefix. Every other argument goes to `train`, and
`--resume <run name>` continues an interrupted run:

```bash
./run_holdout.sh B0_img320 --set data.image_size=320          # Linux
./run_cv.sh --gpu 0 B0_cv --set data.image_size=320
```
```powershell
.\run_holdout.bat B0_img320 --set data.image_size=320          # Windows
```

The working image size is **320 px**, while `config.yaml` still defaults to 224. A
different image size or preprocessing setting builds a separate cache.

## Labels

- `notebooks/02_label_train_reports_*.ipynb` send each report to an LLM with the system
  prompt in `rsna_knee_labeling_system_prompt_v1.txt`. For every finding, the LLM returns
  a status (positive, negative, uncertain or not mentioned; a negative can be marked
  borderline) together with a supporting quote. `metric_calculator/` scores these outputs against the radiologist
  labels.
- `notebooks/build_*.py` turn the extractions into training tables. The default table,
  `train_v8.csv`, has 4199 studies (the 4407 in `train.csv` minus the 208 reference studies).
  It gives a not-mentioned finding the soft target 0.07 instead of 0.25.
- `train_labeled_208_reference.csv` holds the radiologist reference: 158 studies first,
  then 50 more. Every config lists it under `paths.exclude_from_training_csv`, and
  training stops if one of these studies appears in the training pool.

How each status becomes a target and a loss weight is described in the *Label policy*
section of `src/README.md`.

## Inference / submission

`notebooks/04_kaggle_test_online.ipynb` is the Kaggle submission notebook, and
`04_kaggle_test_local.ipynb` is the same notebook pointed at local files for a dry run.
On the test series, the notebook runs manifest → series selection → cache → prediction
in chunks. It averages the sigmoid outputs of the uploaded fold checkpoints and writes
`submission.csv`. Before predicting, it checks that the preprocessing hash it computes
matches the one stored in each checkpoint. Upload each run directory together with its
`config.yaml`. To change the notebooks, edit `notebooks/build_04_notebook.py` and
regenerate them; don't edit the `.ipynb` files directly.
